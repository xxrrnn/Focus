# 03 Execution Map

This document traces the actual execution paths from command line entry to outputs. It focuses on the handoff points that matter for understanding the repository as a system.

## Flow A: Focus Sparse Trace Generation

### User-Facing Command

From `README.md` and `algorithm/run_focus.sh`:

```bash
cd algorithm
python -m run_eval \
  --model llava_vid \
  --model_args pretrained=lmms-lab/LLaVA-Video-7B-Qwen2,conv_template=qwen_1_5,max_frames_num=64,mm_spatial_pool_mode=average \
  --tasks videomme \
  --focus \
  --batch_size 1 \
  --log_samples \
  --output_path ./logs_traces/ \
  --limit 10 \
  --export_focus_trace \
  --trace_dir ./output/focus_main/ \
  --trace_name llava_vid_videomme \
  --use_median \
  --trace_meta_dir ./output/
```

### Actual Entry Chain

1. `algorithm/run_eval.py` parses CLI flags in `parse_eval_args`.
2. `algorithm/run_eval.py` enters `cli_evaluate`.
3. `cli_evaluate` builds optional quantization config and calls `lmms_eval.evaluator.simple_evaluate(...)` in `algorithm/lmms-eval/lmms_eval/evaluator.py`.
4. `simple_evaluate` loads the requested model wrapper through `lmms_eval.models.get_model(model).create_from_arg_string(...)`. The registry is in `algorithm/lmms-eval/lmms_eval/models/__init__.py`.
5. `algorithm/lmms-eval/lmms_eval/evaluator.py` enters `evaluate(...)`.
6. `evaluate(...)` checks CLI flags and calls `focus.interface.apply_focus(lm.model, cli_args=cli_args)` when `--focus` is set.
7. `algorithm/focus/interface.py` detects the model family and installs patched forward functions by calling `replace_focus_forward(...)`.
8. The model-specific multimodal preprocessing hook computes patch metadata and calls `self.focus.prepare(...)`. This occurs in files such as:
   - `algorithm/focus/models/llava_video/modeling_llava_video.py`
   - `algorithm/focus/models/minicpmv/modeling_minicpmv.py`
   - `algorithm/focus/models/qwen2_5_vl/modeling_qwen2_5_vl.py`
9. During decoder execution, the patched Qwen2-style forwards call:
   - `Focus.forward(...)` around GEMM inputs and outputs in `algorithm/focus/models/qwen2/modeling_qwen2.py`
   - `Focus.set_token_importance(...)`
   - `Focus.semantic_concentration(...)`
   - `Focus.post_process(...)`
10. `algorithm/focus/main.py` accumulates sparse trace tensors until the sample limit is reached, chooses the median sample when `--use_median` is enabled, writes `meta_data.csv`, and writes the trace `.pth`.

### Main Functions And Methods Entered

| Stage | File | Function / method |
| --- | --- | --- |
| CLI parsing | `algorithm/run_eval.py` | `parse_eval_args` |
| Evaluation driver | `algorithm/run_eval.py` | `cli_evaluate` |
| Eval harness entry | `algorithm/lmms-eval/lmms_eval/evaluator.py` | `simple_evaluate` |
| Model patch activation | `algorithm/lmms-eval/lmms_eval/evaluator.py` | `evaluate` |
| Focus patching | `algorithm/focus/interface.py` | `apply_focus`, `replace_focus_forward`, `get_model_dimensions` |
| Metadata preparation | model-specific files | `prepare_inputs_labels_for_multimodal_get_patch_type`, `get_vllm_embedding`, Qwen2.5-VL custom forward |
| Focus core | `algorithm/focus/main.py` | `prepare`, `forward`, `focus_similarity_concentration`, `semantic_concentration`, `set_token_importance`, `post_process` |
| Patched model internals | `algorithm/focus/models/qwen2/modeling_qwen2.py` | `Qwen2Model_focus_forward`, `Qwen2DecoderLayer_focus_forward`, `Qwen2SdpaAttention_focus_forward`, `Qwen2MLP_focus_forward` |

### Intermediate Artifacts Produced

- Per-sample evaluation logs under `output_path`.
- In-memory Focus trace tensors stored in `Focus.info_dict` and appended to `Focus.focus_info`.
- `trace_meta_dir/meta_data.csv` written by `algorithm/focus/main.py`.
- `trace_dir/trace_name.pth` written by `algorithm/focus/main.py`.

### Output Files

- `algorithm/output/meta_data.csv`
- `algorithm/output/focus_main/<model>_<dataset>.pth`

### Coupling To Later Stages

- `simulator/models/models.py` consumes `meta_data.csv`.
- `simulator/models/sparse_info.py` consumes `focus_main/*.pth`.
- `evaluation_scripts/plot_scripts/ipynb_src/figure_10.ipynb` uses DSE accuracy CSVs generated by the same algorithm infrastructure.

### What To Learn From This Flow

- **Direct observation**: Focus is not run as a separate post-processing pass. It is inserted directly into model forward execution.
- **Direct observation**: trace export is a side effect of real VLM inference, not a standalone trace converter.
- **Reasoned inference**: this design ensures the simulator sees sparsity patterns that come from actual model execution rather than synthetic sparsity assumptions.

## Flow B: Accuracy Evaluation

### User-Facing Commands

Examples from `algorithm/run_original.sh`, `algorithm/run_focus.sh`, `algorithm/run_framefusion.sh`, `algorithm/run_adaptiv.sh`, and `algorithm/run_cmc.sh`.

```bash
cd algorithm
sh run_focus.sh full
sh run_original.sh
sh run_framefusion.sh
sh run_adaptiv.sh full
sh run_cmc.sh full
```

### Actual Entry Chain

1. Shell script expands into one or more `python -m run_eval ...` commands.
2. `algorithm/run_eval.py` follows the same evaluation path as Flow A.
3. After results return, `algorithm/run_eval.py` calls `print_results(args, results)`.
4. `print_results` calls `get_score_from_results(args, results)` to normalize dataset-specific metrics.
5. If `args.write_accuracy` is set:
   - `save_score_to_main_csv(args, score)` writes `accuracy.csv`
   - or `save_score_to_dse_csv(args, score)` writes DSE accuracy CSVs

### Dataset-Specific Score Extraction

- `videomme` uses `videomme_perception_score,none` overall.
- `mlvu` uses `mlvu_perception_score,none`.
- `mvbench` uses `mvbench_accuracy,none`.
- `vqav2` uses `exact_match,none * 100`.
- `mme` sums cognition and perception scores.
- `mmbench` averages CN/EN/RU GPT-eval scores.

All of this logic is in `algorithm/run_eval.py`.

### Output Files

- `algorithm/output/accuracy.csv`
- `algorithm/output/dse_a_m_tile_accuracy.csv`
- `algorithm/output/dse_b_vector_accuracy.csv`
- `algorithm/output/dse_c_block_accuracy.csv`

### Coupling To Later Stages

- `evaluation_scripts/plot_scripts/ipynb_src/table_2.ipynb`, `table_4.ipynb`, and `table_5.ipynb` read these accuracy CSVs directly.

### Key Observation

- **Direct observation**: accuracy reporting is downstream of `lmms-eval`, but the paper-facing CSV contract is hand-coded in `algorithm/run_eval.py`.

## Flow C: Baseline Sparse Behavior Export

### Adaptiv

1. `algorithm/run_adaptiv.sh` runs `python -m run_eval --adaptiv ...`.
2. `algorithm/lmms-eval/lmms_eval/evaluator.py` still calls `apply_focus`, but `algorithm/focus/interface.py` selects the Adaptiv branch.
3. `algorithm/focus/baseline_adaptiv.py` performs token-level merging/pruning during the patched forward path.
4. `Adaptiv.post_process(...)` writes `trace_meta_dir/adaptiv_sparsity.csv` when `--write_sparsity` is set.

### CMC

1. `algorithm/run_cmc.sh` runs `python -m run_eval --CMC ...`.
2. `algorithm/focus/interface.py` selects the CMC branch.
3. `algorithm/focus/baseline_CMC.py` performs CMC-style token filtering and approximation.
4. `CMC.post_process(...)` writes `trace_meta_dir/cmc_sparsity.csv`.

### Important Difference From Focus

- **Direct observation**: Focus exports fine-grained `.pth` traces with per-layer tensors.
- **Direct observation**: Adaptiv and CMC export coarse CSV sparsity summaries only.
- **Reasoned inference**: this matches the simulator design. Focus needs hardware-visible clustering structure; Adaptiv and CMC are modeled using higher-level sparsity rates.

## Flow D: Simulator Consumption Of Traces

### User-Facing Command

```bash
cd simulator
python main.py --model llava_vid --dataset videomme --accelerator focus --trace_dir ../algorithm/output --output_dir results
```

### Actual Entry Chain

1. `simulator/main.py` parses CLI arguments.
2. `simulator/main.py` builds `ModelConfig(model, dataset, trace_dir)` from `simulator/models/models.py`.
3. `ModelConfig.add_seq_len()` reads `trace_dir/meta_data.csv`.
4. `simulator/main.py` builds `SparseInfo(accelerator, model, dataset, model_config, trace_dir)` from `simulator/models/sparse_info.py`.
5. `SparseInfo` loads:
   - `focus_main/<model>_<dataset>.pth` for Focus
   - `adaptiv_sparsity.csv` for Adaptiv
   - `cmc_sparsity.csv` for CMC
6. `simulator/main.py` builds `Accelerator(...)` from `simulator/arch/accelerator.py`.
7. `Accelerator` configures buffer structure, array size, component counts, and area/power sources from `simulator/arch/*.csv`.
8. `simulator/main.py` builds `Simulator(model_config, accelerator, sparse_info)` from `simulator/core/simulator.py`.
9. `Simulator.run()` dispatches to `run_focus`, `run_dense`, `run_adaptiv`, or `run_cmc`.
10. `Simulator.run_focus(...)` loops through blocks and layer types, then calls:
    - `SimulatorComp.run_linear_focus(...)`
    - `SimulatorComp.run_attn_focus(...)`
    - scatter/gather helpers in `simulator/core/simulator_comp.py`
    - memory accounting helpers in `simulator/core/simulator_mem.py`
11. `Simulator.get_energy_breakdown()` adds DRAM, SRAM, and core energy.
12. `simulator/utils/utils.py::save_result(...)` appends a row to the output CSV.

### Important Name Translation

`simulator/core/simulator.py` maps some logical layer names when consuming Focus traces:

- `k_proj` uses `q_proj`
- `v_proj` uses `q_proj`
- `up_proj` uses `gate_proj`
- `attn` uses `query`

This exists because Focus only records a subset of projection sites explicitly in `algorithm/focus/main.py`.

### Output Files

- `results/main_focus.csv`
- `results/main_dense.csv`
- `results/main_adaptiv.csv`
- `results/main_cmc.csv`
- `results/detailed_power_area_breakdown.csv` for one specific default Focus case

### What To Learn From This Flow

- **Direct observation**: simulator input is completely file-based.
- **Direct observation**: the simulator’s architectural study is independent from the Python VLM runtime once traces exist.
- **Reasoned inference**: this is the main methodology bridge between paper algorithm claims and paper hardware claims.

## Flow E: DSE And Special Simulator Modes

### Focus DSE

1. `algorithm/run_dse.sh` generates traces or rough accuracy samples for:
   - GEMM `m_tile_size`
   - `block_size`
   - `vector_size`
2. `simulator/run_dse_sim.sh` invokes the corresponding simulator DSE modes in `simulator/main.py`.

### Important Caveat

- **Direct observation**: `simulator/main.py::dse_vector_size(...)` does not run a full end-to-end model simulation. It calls `simulator.run_layer_wise_focus(sparse_info, "o_proj", 9, vector_size)`.
- **Reasoned inference**: vector-size DSE is a targeted layer-wise analysis, not a whole-model latency study in the same sense as the other DSE modes.

### SEC-Only Ablation

1. `simulator/main.py --SEC_only --accelerator focus ...`
2. `main(args)` halves `focus_m_tile_size` from `1024` to `1024 // 2`.
3. Results are saved to `main_focus_SEC_only.csv`.

### INT8 Path

1. `algorithm/run_focus.sh int8` writes `focus_int8/*.pth`.
2. `simulator/main.py --quantization --accelerator focus ...` loads those traces through `SparseInfo(..., dse="quantization")`.
3. Results are saved to `int8_focus.csv`.

## Flow F: Plotting And Final Paper Artifacts

### User-Facing Step

Open notebooks in `evaluation_scripts/plot_scripts/ipynb_src/` and run them with the expected CSVs available.

### Actual Data Flow

1. Notebook reads CSVs from `simulator/example_sim_results/` or a user-provided result directory.
2. Some notebooks also read `algorithm/example_output/accuracy.csv` or the generated `algorithm/output/accuracy.csv`.
3. Each notebook derives normalized speedup, energy, sparsity, or accuracy values and renders a figure/table.

### Example

- `evaluation_scripts/plot_scripts/ipynb_src/figure_9.ipynb` reads:
  - `main_dense.csv`
  - `main_adaptiv.csv`
  - `main_cmc.csv`
  - `main_focus.csv`
  - `evaluation_scripts/jetson_stats/figure9_gpu.csv`

### Key Observation

- **Direct observation**: the notebook layer consumes CSVs only; it never calls back into the simulator or algorithm code.

## Flow G: RTL To Simulator Linkage

1. RTL modules live in `rtl/`.
2. `rtl/README.md` explains the intended architectural grouping of those modules.
3. `simulator/arch/accelerator.py` reads `focus_rtl.csv`, `adaptiv_rtl.csv`, and `cmc_rtl.csv`.
4. Those CSVs provide the component area/power values used in simulator breakdowns.

### Important Boundary

- **Direct observation**: there is no checked-in path where `simulator/` executes RTL.
- **Reasoned inference**: the connection is “RTL synthesis statistics feed simulator,” not “simulator drives RTL.”

## Bottom Line

- **Direct observation**: the repository’s true execution path is `run_eval.py -> serialized sparsity/metadata -> simulator/main.py -> CSVs -> notebooks`.
- **Reasoned inference**: this is the central methodology of the project. The algorithm and accelerator are coupled through measured sparse behavior, not through a shared runtime.
- **Unclear**: the exact scripts used by the authors to move outputs between stages are not centralized; the user is expected to manage output directories consistently.
