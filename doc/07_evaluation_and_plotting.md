## How Paper Figures Are Generated

## Figure 9

- **Direct observation**: `figure_9.ipynb` reads simulator outputs from a result directory and `evaluation_scripts/jetson_stats/figure9_gpu.csv`.
- **Direct observation**: it computes speedup normalized to dense baseline and stacks energy into `dram_energy`, `sram_energy`, and `core_energy`.
- **Reasoned inference**: Figure 9 is the main “system-level payoff” figure because it combines algorithm-derived traces, simulator results, and external GPU measurements.

## Figure 10

- **Direct observation**: `figure_10.ipynb` is the main DSE notebook.
- **Direct observation**: it reads simulator CSVs for:
  - m-tile size
  - vector size
  - block size
  - scatter-accumulator count
- **Direct observation**: it also reads algorithm-generated DSE accuracy CSVs.
- **Reasoned inference**: this notebook is where algorithm-side accuracy sensitivity and simulator-side hardware sensitivity are joined.

## Figure 11

- **Direct observation**: `figure_11.ipynb` compares:
  - dense
  - CMC
  - Focus SEC-only
  - full Focus
- **Reasoned inference**: this notebook is the clearest expression of the claimed contribution split between SEC and SIC.

## Figure 12

- **Direct observation**: `figure_12.ipynb` reads `total_dram_access` and `total_activation` from simulator outputs.
- **Reasoned inference**: this figure depends on the memory-accounting logic in `simulator/core/simulator_mem.py` and the activation counting in `simulator/core/simulator.py`.

## Figure 13

- **Direct observation**: Figure 13 is not produced by a notebook. It is generated by `simulator/utils/analysis.py`.
- **Direct observation**: that script reads Focus traces through `ModelConfig` and `SparseInfo`, computes per-tile non-similar-vector counts, and writes `figure_13.svg`.

## How Plotting Depends On Algorithm And Simulator Outputs

- **Direct observation**: all accuracy values come from `algorithm/run_eval.py` outputs.
- **Direct observation**: all latency, energy, DRAM, and operation counts come from `simulator/main.py` outputs.
- **Direct observation**: the notebooks do not regenerate traces or rerun simulation.
- **Reasoned inference**: the plotting layer is intentionally passive; it assumes the CSVs are already correct.

## Practical Caveats

- **Direct observation**: notebook paths are written relative to the notebook location and often point to `simulator/example_sim_results/` or `algorithm/example_output/`.
- **Reasoned inference**: if you generate fresh outputs elsewhere, you will need to edit notebook path variables rather than expect auto-discovery.
- **Direct observation**: because the notebooks derive normalized metrics, missing one CSV usually breaks multiple plots downstream.

## Methodology Lesson

- **Reasoned inference**: this repository uses a good research pattern here. Paper visualization is fully downstream of computation. That keeps the algorithm and simulator code cleaner, and it makes it easier to rerun figures from archived CSVs later.
